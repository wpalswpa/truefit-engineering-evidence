# 001. 생성 문장 대신 원문 구간을 반환하게 한다

- 상태: 채택 (2026-09, 구간 선택 도입 2026-09-14)
- 맥락: 트루핏은 운동 수업 계약서에서 금액·환불·노쇼 조항을 뽑아 회원에게 보여 준다.

## 문제

모델에 요약을 맡기면 문장은 매끄럽게 나온다. 그런데 그 문장이 원문에 실제로 있었는지
확인할 방법이 없다. 계약 분쟁에 쓰이는 화면이라 "그럴듯한 요약"은 위험하다.

## 검토한 대안 (2026-09-22 사후 정리)

이 표는 채택 뒤 공개용으로 정리한 것이다. 당시 결정 과정의 기록이 아니라, 선택을 설명하기 위해 되돌아보며 쓴 비교다.

| 방식 | 선택을 가른 이유 | 판단 |
|---|---|---|
| 생성 후 유사도 검증 | 채택할 임계값을 정할 근거가 없었다. 0.8이면 되는지 0.9여야 하는지 말할 수 없다 | 미채택 |
| 생성 후 사람이 확인 | 검토 건수가 늘수록 수동 확인이 밀린다. 밀리면 확인을 건너뛰게 된다 | 미채택 |
| 위치 선택 + 서버 추출 | 모델이 문장을 쓰지 않으므로 검증할 대상 자체가 줄어든다 | **채택** |

## 결정

원문을 문장 단위로 쪼개 1부터 번호를 매기고, 모델에게는 `kind`·`first`·`last`
세 필드만 반환하게 한다. 인용문은 서버가 `source[start:end]` 로 직접 만든다.

```python
rows.append({"quote": source[start:end], ...})   # 모델 응답이 아니라 원문에서
```

## 결과

**막는 것.** 모델이 새로 쓴 문장이 인용문에 섞이는 경로. 구조적으로 통로가 없다.
`tests/test_contract_examples.py::test_model_generated_quote_is_never_rendered`

**막지 못하는 것.** 모델이 존재하는 ID 중에서 틀린 구간을 고르거나, 조건이 빠진 범위를
고르거나, `kind` 를 잘못 분류하는 것. 원문에서 가져왔다는 사실과 올바른 근거를 골랐다는
사실은 다르다. 후자는 별도의 의미 검증이 필요하고, 아직 하지 않았다.

**대가.** 세그먼트 단위로만 인용하니 문장 중간을 집어낼 수 없다.
원문에 *없는* 조항(누락된 조항)은 구조적으로 찾지 못한다.
