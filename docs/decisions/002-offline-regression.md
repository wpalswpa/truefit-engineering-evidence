# 002. 저장된 응답으로 검증 로직만 회귀 검사한다

- 상태: 채택 (2026-09)
- 맥락: 001의 검증 계층(스키마 검사·ID 복원·예외 처리)을 고칠 때마다 회귀가 필요하다.

## 문제

검증 코드를 고칠 때마다 모델을 호출해 전부 돌리면 두 가지가 생긴다.
비용이 들고, 응답이 매번 달라 결과가 흔들린다. 그러면 검사를 건너뛰게 되고,
건너뛰기 시작하면 검사가 없는 것과 같다.

## 검토한 대안

| 방식 | 선택을 가른 이유 | 판단 |
|---|---|---|
| 모델을 목(mock)으로 대체 | 실제 응답의 형태와 어긋난 것을 놓친다 | 미채택 |
| 과거 응답을 스냅샷으로 고정 | 결정론적이고 무료다. 대신 검증 범위가 좁아진다 | **채택** |

## 결정

`gpt-4.1-mini` 의 과거 응답을 스냅샷으로 고정하고, 경계 4종(조건 누락·부정어·
범위 밖 인용·지시문 주입)을 합성 입력 11건으로 만들어 API 호출 없이 재검사한다.

## 결과

**검증하는 것** — 저장된 응답에 대한 *처리 로직*이 이전과 같이 동작하는가.
스키마 검사, ID 복원, 예외 처리가 그 대상이다.

**검증하지 못하는 것** — 프롬프트나 모델을 바꿨을 때의 **생성 품질 변화**.
저장된 응답을 다시 채점하는 방식이므로, 새 프롬프트가 더 잘 답하는지는 알 수 없다.
그건 새로 호출해 채점하는 평가가 따로 필요하고, 아직 하지 않았다.

두 평가를 한 검사에 섞지 않은 이유가 여기 있다. 섞으면 실패했을 때
검증 코드가 깨진 것인지 모델 출력이 달라진 것인지 구분할 수 없다.

`evidence/gate-summary.json` 의 `ai_review.limits` 에 같은 내용이 기록돼 있다.
